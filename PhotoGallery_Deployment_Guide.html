📸 Photo Gallery App

Complete step-by-step deployment guide for the AWS serverless photo gallery — S3, Lambda, API Gateway, Cognito & DynamoDB.

Region: ap-south-1 Serverless Architecture Cognito Auth Python 3.12 Lambda Developed by Krishna Yada

Overview & Architecture

This is a serverless photo gallery application built entirely on AWS. Users authenticate through Amazon Cognito, upload photos to a private S3 bucket via Lambda-generated presigned URLs, and view only their own photos. The browser never holds AWS credentials — all S3 access is brokered by Lambda functions sitting behind API Gateway. Photo metadata (filename, owner, upload date) is stored in DynamoDB.

1Create the DynamoDB Table

DynamoDB stores metadata for every uploaded photo — filename, S3 key, upload timestamp, and the owner's Cognito sub (user ID). One item per photo.

Console

  1. Open DynamoDB in the AWS Console → click Create table.
  2. Table name: PhotoGallery
  3. Partition key: photoId — type String. Leave sort key empty.
  4. Table settings: choose Customize settings → Capacity mode: On-demand (pay-per-request, no capacity planning needed).
  5. Leave all other settings as default → click Create table.
  6. Wait until the table status shows Active (usually under 30 seconds).

CLI

aws dynamodb create-table \
  --table-name PhotoGallery \
  --attribute-definitions AttributeName=photoId,AttributeType=S \
  --key-schema AttributeName=photoId,KeyType=HASH \
  --billing-mode PAY_PER_REQUEST \
  --region ap-south-1

Verify

aws dynamodb describe-table \
  --table-name PhotoGallery \
  --region ap-south-1 \
  --query "Table.TableStatus"
# Expected output: "ACTIVE"
DynamoDB is schemaless — only photoId is declared. The other fields (fileName, s3Key, uploadDate, userSub, contentType) are written by Lambda at upload time and require no pre-declaration.

3Create the IAM Role for Lambda

Both Lambda functions share one execution role: serverless-capstone-01062026. This role grants Lambda permission to write CloudWatch logs, read/write DynamoDB, and generate presigned S3 URLs.

Console

  1. IAM → Roles → Create role.
  2. Trusted entity: AWS service → Lambda → Next.
  3. Search and attach these managed policies:
    • AWSLambdaBasicExecutionRole — CloudWatch Logs write access.
    • AmazonDynamoDBFullAccess — read/write the PhotoGallery table.
    • AmazonS3FullAccess — generate presigned URLs and access objects.
  4. Role name: serverless-capstone-01062026 → Create role.

CLI

# 1. Create the role with Lambda trust policy
aws iam create-role \
  --role-name serverless-capstone-01062026 \
  --assume-role-policy-document '{
    "Version":"2012-10-17",
    "Statement":[{"Effect":"Allow","Principal":{"Service":"lambda.amazonaws.com"},"Action":"sts:AssumeRole"}]
  }'

# 2. Attach managed policies
aws iam attach-role-policy --role-name serverless-capstone-01062026 \
  --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole

aws iam attach-role-policy --role-name serverless-capstone-01062026 \
  --policy-arn arn:aws:iam::aws:policy/AmazonDynamoDBFullAccess

aws iam attach-role-policy --role-name serverless-capstone-01062026 \

Least-privilege tip (production). Replace *FullAccess with a custom policy scoped to the specific table ARN (arn:aws:dynamodb:ap-south-1:359642223341:table/PhotoGallery) and the data bucket ARN (arn:aws:s3:::krishna01062026data/*), allowing only the actions Lambda actually needs.

4Create the Lambda Functions

Two functions handle all backend logic. Both use Python 3.12 and the serverless-capstone-01062026 IAM role.

4a · uploadPhoto

Receives photo metadata from the frontend, saves a record to DynamoDB, and returns a presigned S3 PUT URL so the browser can upload the file directly to S3.

  1. Lambda → Create function → Author from scratch.
  2. Function name: uploadPhoto · Runtime: Python 3.12.
  3. Execution role: Use an existing role → serverless-capstone-01062026.
  4. Click Create function, then paste the code below into the inline editor and click Deploy.
  5. Configuration → Environment variables → Edit → Add:

    PHOTO_BUCKET_NAME = krishna01062026data

  6. Configuration → General configuration → Edit → Timeout: 30 seconds → Save.
import json, boto3, uuid, os
from datetime import datetime

s3 = boto3.client('s3')
dynamodb = boto3.resource('dynamodb')
TABLE_NAME = 'PhotoGallery'
BUCKET = os.environ['PHOTO_BUCKET_NAME']

def lambda_handler(event, context):
    headers = {
        'Access-Control-Allow-Origin': '*',
        'Access-Control-Allow-Headers': 'Content-Type,Authorization',
        'Access-Control-Allow-Methods': 'POST,OPTIONS'
    }
    try:
        claims  = event['requestContext']['authorizer']['claims']
        user_sub   = claims['sub']
        user_email = claims.get('email', '')
        body     = json.loads(event.get('body') or '{}')
        filename = body['fileName']
        content_type = body.get('contentType', 'image/jpeg')

        photo_id = str(uuid.uuid4())
        s3_key   = f"photos/{user_sub}/{photo_id}_{filename}"

        # Save metadata to DynamoDB
        dynamodb.Table(TABLE_NAME).put_item(Item={
            'photoId':     photo_id,
            'fileName':    filename,
            's3Key':       s3_key,
            'uploadDate':  datetime.utcnow().isoformat(),
            'contentType': content_type,
            'userSub':     user_sub,
            'userEmail':   user_email
        })

        # Generate presigned PUT URL (5-minute expiry)
        presigned_url = s3.generate_presigned_url(
            'put_object',
            Params={'Bucket': BUCKET, 'Key': s3_key, 'ContentType': content_type},
            ExpiresIn=300
        )
        return {
            'statusCode': 200,
            'headers': headers,
            'body': json.dumps({'uploadUrl': presigned_url, 'photoId': photo_id, 's3Key': s3_key})
        }
    except Exception as e:
        return {'statusCode': 500, 'headers': headers, 'body': json.dumps({'error': str(e)})}

4b · listPhotos

Scans DynamoDB for photos belonging to the authenticated user and returns each one with a presigned GET URL so the browser can display the image.

  1. Lambda → Create function → name listPhotos, same runtime and role.
  2. Paste the code below → Deploy.
  3. Add env var PHOTO_BUCKET_NAME = krishna01062026data.
  4. Set timeout to 30 seconds.
import json, boto3, os
from boto3.dynamodb.conditions import Attr
from decimal import Decimal

s3 = boto3.client('s3')
dynamodb = boto3.resource('dynamodb')
TABLE_NAME = 'PhotoGallery'
BUCKET = os.environ['PHOTO_BUCKET_NAME']

class DecimalEncoder(json.JSONEncoder):
    def default(self, o):
        return float(o) if isinstance(o, Decimal) else super().default(o)

def lambda_handler(event, context):
    headers = {
        'Access-Control-Allow-Origin': '*',
        'Access-Control-Allow-Headers': 'Content-Type,Authorization',
        'Access-Control-Allow-Methods': 'GET,OPTIONS'
    }
    try:
        user_sub = event['requestContext']['authorizer']['claims']['sub']
        table    = dynamodb.Table(TABLE_NAME)

        # Filter to only this user's photos
        result = table.scan(FilterExpression=Attr('userSub').eq(user_sub))
        photos = result['Items']

        # Paginate if table has more than 1 MB of data
        while 'LastEvaluatedKey' in result:
            result = table.scan(
                FilterExpression=Attr('userSub').eq(user_sub),
                ExclusiveStartKey=result['LastEvaluatedKey']
            )
            photos.extend(result['Items'])

        # Attach a presigned GET URL to each photo (15-minute expiry)
        for photo in photos:
            photo['viewUrl'] = s3.generate_presigned_url(
                'get_object',
                Params={'Bucket': BUCKET, 'Key': photo['s3Key']},
                ExpiresIn=900
            )

        photos.sort(key=lambda x: x.get('uploadDate', ''), reverse=True)
        return {
            'statusCode': 200,
            'headers': headers,
            'body': json.dumps({'photos': photos, 'count': len(photos)}, cls=DecimalEncoder)
        }
    except Exception as e:
        return {'statusCode': 500, 'headers': headers, 'body': json.dumps({'error': str(e)})}
Per-user isolation is built in. listPhotos reads the caller's Cognito sub from the authorizer claims and returns only that user's photos. A second user signing in will see an empty gallery until they upload their own photos.
The table name PhotoGallery is hard-coded as TABLE_NAME in both files. If your table name differs, update that constant before deploying.

5Create the API Gateway

API Gateway exposes two HTTP endpoints that the frontend calls. It validates the Cognito JWT before forwarding requests to Lambda.

5a · Create the REST API

  1. API Gateway → Create API → REST API → Build.
  2. API name: PhotoGalleryAPI · Endpoint type: Regional → Create API.

5b · Create the /photos resource

  1. In the Resources panel, select the root / → Create Resource.
  2. Resource name: photos (path: /photos).
  3. Tick Enable API Gateway CORS → Create Resource.

5c · Create GET and POST methods

  1. Select /photos → Create Method → GET:
    • Integration type: Lambda Function
    • ✅ Lambda Proxy integration: ON
    • Lambda function: listPhotos (region ap-south-1)
  2. Select /photos → Create Method → POST:
    • Integration type: Lambda Function
    • ✅ Lambda Proxy integration: ON
    • Lambda function: uploadPhoto
Lambda Proxy integration must be ON. The Lambda code reads event['requestContext']['authorizer']['claims'] and event['body'] — these only exist when proxy integration is enabled.

5d · Enable CORS on the resource

  1. Select /photos → Enable CORS.
  2. Allow headers: Content-Type,Authorization,X-Amz-Date,X-Api-Key,X-Amz-Security-Token
  3. Allow methods: GET, POST, OPTIONS · Origin: * (or your hosting URL for production).
  4. Save and confirm the OPTIONS method is created.

5e · Deploy to a stage

  1. Deploy API → New stage → name prd → Deploy.
  2. Copy the Invoke URL:

https://ypq5mzgr00.execute-api.ap-south-1.amazonaws.com/prd

You will deploy the API again after attaching the Cognito authorizer in Step 7. The authorizer is not active until the API is redeployed.

6Set Up Cognito Authentication

Cognito handles user sign-up, sign-in, and issues the JWT tokens that API Gateway validates.

6a · Create the User Pool

  1. Cognito → Create user pool.
  2. Sign-in option: Email → Next.
  3. Password policy: keep defaults (min 8 chars, upper, lower, number, symbol).
  4. MFA: No MFA (for this demo) → Next.
  5. Self-service sign-up: Enable. Auto-verify: Email → Next.
  6. Email delivery: Send email with Cognito → Next.
  7. User pool name: PhotoGalleryUsers → Next.

6b · Create the App Client

  1. App type: Public client (no client secret — browser app).
  2. App client name: PhotoGalleryUsers.
  3. Auth flows: enable ALLOW_USER_SRP_AUTH, ALLOW_REFRESH_TOKEN_AUTH.
  4. Note the App client ID: 3k798826doeh2bnbld9qb4p5b6.

6c · Configure the Hosted UI domain

  1. App integration → Domain → Create Cognito domain.
  2. Domain prefix: krishna → creates krishna.auth.ap-south-1.amazoncognito.com.

6d · Configure OAuth / Hosted UI settings

  1. App integration → select your app client → Edit Hosted UI.
  2. OAuth grant type: Implicit grant.
  3. OpenID Connect scopes: email, openid.
  4. Allowed callback URLs: 
    http://krishna01062026hosting.s3-website.ap-south-1.amazonaws.com/
http://krishna01062026hosting.s3-website.ap-south-1.amazonaws.com/index.html
http://localhost:5500/index.html
  5. Allowed sign-out URLs: same list as above.
  6. Save changes.
Callback URL must match exactly. The frontend uses window.location.href as the redirect URI. Register both / and /index.html variants so either entry point works — a mismatch causes a redirect_mismatch error at login.

  2. Enter an email address, set a temporary password, mark email as verified.

7Attach the Cognito Authorizer to API Gateway

This step locks down the GET and POST methods so only authenticated users can call them.

  1. API Gateway → PhotoGalleryAPI → Authorizers → Create New Authorizer.
  2. Name: CognitoAuth · Type: Cognito.
  3. Cognito User Pool: select ap-south-1_l8Q8UF6XP (region ap-south-1).
  4. Token source: Authorization (exactly this — no "Bearer" prefix).
  5. Click Create Authorizer. You can test it by pasting a valid id_token from Cognito.
  6. Go to /photos → GET → Method Request → Authorization → select CognitoAuth → tick the checkmark.
  7. Repeat for /photos → POST → Method Request → Authorization → CognitoAuth.
  8. Deploy API → prd to apply the authorizer changes.
The frontend sends the raw id_token in the Authorization header (no Bearer prefix). Keep the token source as Authorization to match. If you add "Bearer", the authorizer will reject every request.
After attaching the authorizer, calling GET /photos without a token returns 401 Unauthorized. This is correct — it confirms the authorizer is working.

Troubleshooting

SymptomLikely cause & fix
401 Unauthorized on GET or POSTAuthorizer token source isn't Authorization, or the API wasn't redeployed after attaching the authorizer (Step 7).
CORS error in browser consoleData bucket missing CORS config (Step 2a) and/or CORS not enabled on the /photos API resource (Step 5d).
redirect_mismatch at Cognito loginThe current page URL isn't in Cognito's allowed callback URLs. Register both / and /index.html variants (Step 6d).
Upload returns 403 from S3Content-Type on the PUT doesn't match the signed type, or the presigned URL expired (5 min). Re-request a new URL.
Broken / missing photosPresigned GET URL expired (15 min) — reload the page to get fresh URLs. Or Lambda lacks S3 permissions — check the IAM role.
"PHOTO_BUCKET_NAME not set"Add the environment variable to both Lambda functions (Step 4).
Lambda returns 500Check CloudWatch Logs: /aws/lambda/uploadPhoto or /aws/lambda/listPhotos. Common cause: missing env var or IAM permission.
User sees other users' photosOld listPhotos doing an unfiltered scan. Redeploy the version that filters by userSub.
API Gateway returns 500 on first callLambda invoke permission missing. API Gateway must have permission to invoke the Lambda function — this is added automatically when you create the method via the console.

Teardown / Cleanup

To avoid ongoing charges, delete all resources in this order:

  1. API Gateway → delete PhotoGalleryAPI.
  2. Lambda → delete uploadPhoto and listPhotos.
  3. Cognito → delete user pool ap-south-1_l8Q8UF6XP (and its domain krishna).
  4. DynamoDB → delete table PhotoGallery.
  5. Empty both S3 buckets, then delete them.
  6. IAM → delete role serverless-capstone-01062026.
  7. CloudWatch → delete log groups /aws/lambda/uploadPhoto and /aws/lambda/listPhotos.
# Empty and delete S3 buckets
aws s3 rm s3://krishna01062026data --recursive --region ap-south-1
aws s3 rm s3://krishna01062026hosting --recursive --region ap-south-1
aws s3api delete-bucket --bucket krishna01062026data --region ap-south-1
aws s3api delete-bucket --bucket krishna01062026hosting --region ap-south-1

# Delete DynamoDB table
aws dynamodb delete-table --table-name PhotoGallery --region ap-south-1
Irreversible. Emptying the data bucket permanently destroys all uploaded photos. There is no recycle bin.
